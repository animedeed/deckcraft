# /deck-review — разбор колоды

Пути — от базы скилла; движок `../pptx-morph/scripts`. Колоду не меняешь — только отчёт.

## 1. Снять материал
```
from morphkit.existing import Deck
from morphkit.qa import render, contact_sheet, xsd_check, lo_effects_check
from morphkit.motion import preview
d = Deck(path); slides = d.to_slides()
pngs = render(path, out/"png"); contact_sheet(pngs, out/"sheet.png")
preview(slides, d.theme, out/"motion", gif=False)        # ленты кадров каждого перехода
```
`to_slides()` — эскиз: цвета схемы без оттенков, картинки — серые рамки. Для колод morphkit бери настоящие `Slide`.
Плюс `d.report()` (пары, переходы, эффекты), `xsd_check`, `lo_effects_check`.

## 2. Оценить
Смотри миниатюры как незнакомый зритель, потом по пунктам:
- **Первое впечатление** — что видно за 2 секунды, понятна ли тема и стиль.
- **Читаемость** — кегль, длина строк, переполнение, контраст (≥ 4,5:1 для текста, ≥ 3:1 для крупного).
- **Иерархия** — один фокус, три уровня, заголовок-вывод.
- **Единообразие** — одна навигация, один тип перехода между разделами, замок стиля, сетка.
- **Ритм колоды** — смена плотности, «вау» на раздел, рифма начала и конца (`../pptx-design/references/rhythm.md`).
- **Движение** — по лентам: у перехода есть смысл, фигуры не пролетают по тексту, нет одинаковых приёмов подряд,
  Morph ≤ 0,9 с, петли только у процессов, нет отвергнутых приёмов (`../pptx-morph/references/techniques.md`).
- **Антишаблоны** — `../pptx-design/references/design-system.md` §6.
Если установлен плагин Design (`design:design-critique`, `design:accessibility-review`) — используй его структуру.

## 3. Отчёт
Сначала 2–3 сильные стороны (их не трогать при правке). Затем таблица:
`серьёзность (критично / заметно / мелочь) · слайд · что видно · почему мешает · правка · инструмент`.
Не больше 12 строк, критичное сверху. В конце: «Поправить? — /deck-remix сделает пункты 1–N».
Приложи лист миниатюр и 1–2 ленты движения с проблемой (SendUserFile, render).
