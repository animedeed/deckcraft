# Концепт колоды: сквозной мотив, грамматика процесса, палитра

Сложные трансформации работают, когда они идут **через всю колоду**, а не стоят «фокусом» на одном слайде. Для этого
у колоды три сквозные вещи:

1. **мотив** — один объект-герой, который меняет роль (обложка → указатель → фон → диаграмма → портал → финал);
2. **носитель процесса** — элементы, которые проходят через процесс (токены, строки, документы, пары) и меняют
   состояние от шага к шагу;
3. **палитра** с короткой причиной, почему она подходит теме.

Модули: `morphkit.motif`, `morphkit.process`, `morphkit.palette`. Галерея всех ролей и глаголов —
`scripts/gallery_concepts.py OUT [ink|lab|neuro|…]`. Пример колоды целиком — `scripts/examples/demo_deck.py`.

## 1. Мотив в ролях (`MotifTrack`)

| Роль | Что на экране | Когда |
|---|---|---|
| `hero` | мотив крупно, справа или в центре | обложка, финал (рифма начала и конца) |
| `pointer` | наполовину за левым краем, часть k (лепесток, тело) смотрит на заголовок; `part=0.5` — полосы части k залиты на 50 % (прогресс тем раздела) | раздел k; на темах раздела мотив стоит, заливаются деления |
| `backdrop` | огромный, прозрачность ~8–10 %, под всем (z = −400); `next_k` — заранее повёрнут под следующий раздел, чтобы вернуться в указатель без вращения | слайды-графики и таблицы: «колода дышит», текст читается |
| `progress` | маленький навигатор в углу: раскрыто k+1 частей из n | длинные колоды без разделов-указателей |
| `data` | размеры частей = значения, подписи по кольцу | 3–12 величин одной природы (важности, доли); подписи могут быть подписями фишек носителя — тогда фишки «перелетают» к лепесткам |
| `portal` | центральный диск раздувается на весь экран цветом фона | **только если так входят во все разделы**; пользователю пока не нравится — по умолчанию не использовать |
| `seed` | мотив свёрнут в точку | не использовать: «вдруг маленький» (отзыв пользователя) |

Правила:
- одна колода — один мотив; роль меняется не чаще чем через 1–3 слайда, иначе мотив отвлекает;
- `pointer` → `pointer` соседнего раздела: поворот на одну часть (шаг < 180° обеспечивает `MotifTrack`);
- `data` только там, где части мотива и правда соответствуют величинам (12 лепестков = 12 входов модели);
- `portal` — только как единый тип перехода во ВСЕ разделы (иначе чужой); следующий слайд начинается с «пустого» фона;
- после `backdrop` текст и графики лежат поверх: проверь контраст (lint) и не клади подписи на самые плотные части.
- Мотивы: `Flower` (многослойные лепестки, эталон — видео пользователя), `Orbit` (орбиты и тела, солнце — портал).
  Новый мотив = класс с `objs(theme, center, scale, turn, alpha, sizes, focus, disc_scale)`, `facing(k)`, `tip(k)`
  и постоянными именами частей.

## 2. Грамматика процесса (`Carrier` + глаголы)

Тяжёлый процесс («как модель находит ошибку в тексте», «как идёт обучение», «как правка расходится по документам»)
раскладывается на **шаги-глаголы**. Каждый глагол — новое состояние одних и тех же объектов-носителей:

| Глагол | Состояние носителя | Пример |
|---|---|---|
| `split` | `row` / `groups` | фраза → токены; данные → train/val/test |
| `encode` | `vectors` | токен → столбец эмбеддинга; строка → точка |
| `relate` | `links` (дуги) | внимание, ссылки, граф |
| `score` | `bars` | вероятность ошибки, важность |
| `flag` | `row(flagged=True)` + `flag_loops()` | найдено главное (ошибка, аномалия) |
| `filter` | `filtered` | отсеянное сжимается в точку-след |
| `aggregate` | `merged` | части сливаются в результат |
| `compare` | два состояния рядом | было / стало, прогноз / факт |
| `cluster` | `groups` | расхождение по группам |
| `zoom` | камера мира или прожектор | одна часть крупно |
| `iterate` | `R.curve` + маркер | эпохи, итерации |

Имена носителя постоянны: тело `!!{id}{i}` (без текста) и подпись `!!{id}{i}t` — поэтому тело переливается из фишки
в точку, столбик или ячейку, а подпись едет следом и не «кашит» буквами (текст не меняется). `plan(verbs)` проверяет
раскадровку: известные глаголы, нет трёх одинаковых подряд, есть кульминация (`flag`, `aggregate` или `compare`).

### Протокол «текст → структура» (что делает навык или плагин по описанию задачи)

1. **Прочитать текст задачи** и выписать: кто проходит процесс (носитель), какие шаги с ним происходят (глаголы),
   что в конце (результат), где главный момент (кульминация), какие есть числа.
2. **Выбрать носитель**: то, что зритель может узнать на каждом шаге (слова фразы, строки, документы). Если носителей
   два (например, признаки и образцы) — у каждого свой участок колоды; мост между ними — мотив.
3. **Записать цепочку глаголов** (8–14 шагов на доклад), прогнать `plan()`.
4. **Выбрать мотив и раздать роли**: обложка `hero`, разделы `pointer` (или `progress`), графики — `backdrop`,
   данные «по частям» — `data`, темы раздела — `pointer(k, part=…)`, финал — `hero`; переход между разделами — один тип на колоду.
5. **Подобрать палитру** `palette.suggest(тема)` — показать 2–3 варианта с причиной; без ответа брать первый.
6. **Показать раскадровку** таблицей: № · слайд · макет · глагол/приём на переходе (как `scripts/examples/demo_storyboard.md`).
   После согласования — сборка, затем проверка: `lint`, `xsd_check`, `lo_effects_check`, рендер и лист миниатюр.

## 3. Палитра с причиной (`palette.suggest`)

Каталог — 12 направлений (`CATALOG`): Лаборатория, Погреб, Чертёж, Тушь, Диспетчерская, Нейросеть, Реестр, Клиника,
Гроссбух, Лес, Класс, Космос. У каждого — теги темы и одна строка «почему». `suggest(text, k=3)` возвращает
варианты с причиной (`p.reason`: «почему» + слова темы, по которым она выбрана); в выдаче всегда есть светлая и тёмная
гамма. Если тема не узнана — нейтральные: Тушь, Класс, Чертёж. `check_catalog()` — контраст всех тем (пусто = ок).

Подпись для пользователя — одна строка: «**Диспетчерская** — мнемосхема диспетчера: тёмно-синий фон, бирюзовые
связи, янтарь — внимание. В теме: электросетях.»

## 4. Проверки, которые ловят баги концепта

- `lint`: тексты не налезают друг на друга (подписи лепестков на заголовок, подписи групп друг на друга); строки
  помещаются (`fit_text` переносит заранее); шаг поворота < 180°; фон под текстом.
- `lo_effects_check(pptx)`: все эффекты узнаны LibreOffice (`ok: True`); свои траектории сигнала — отдельно.
- Рендер и лист миниатюр: фон-мотив не лёг поверх графика; подписи носителя у нужных частей; нет «придуманных»
  чисел (каждое число на слайде — из файлов проекта).


## 5. Операторы движения (`morphkit.ops`) — анимация для любой формы

Оператор берёт состояние (список фигур) и возвращает новое с теми же именами — Morph переводит одно в другое.
Один оператор работает на лепестках, точках, карточках, орбитах, фрагментах; операторы компонуются в цепочки.

| Оператор | Что делает | Для чего |
|---|---|---|
| `explode` / `gather` / `scatter` | разлёт от центра / сбор в точку / рассыпание | устройство, сжатие, хаос → порядок |
| `orbit` / `swirl` / `fan` | поворот системы / вихрь (внешнее сильнее) / веер вокруг точки | цикл, «затягивание», выбор вариантов |
| `wave` / `colorwave` / `cascade` | волна смещения / волна цвета / каскад появления по расстоянию | сигнал прошёл, распространение |
| `along` / `peel` / `lift` | вдоль кривой / лесенкой слоёв / выдвинуть к зрителю с тенью | время, версии, выбранная тема |
| `tilt3d` / `recede` / `squash` / `shear` / `fold` | наклон плоскости с перспективой / уход к точке схода / сплющивание / сдвиг / сгиб | 2D → 3D: вид сверху, фон в глубине, орбита, грань, лист |

Псевдо-3D — на контурах: сначала `to_vec(objs, n)` (фиксированное число точек), затем `tilt3d` / `recede` —
переливается плавно. Семейство `lab/f_ops.py` показывает каждый оператор на пяти базах и цепочки из 2–3 операторов.

## 6. Проверка движения

- `motion.preview(slides, theme, out, which=[…])` — ленты кадров и GIF переходов (Morph, эффекты, петли). Смотреть
  каждую ленту: что исчезает вместо перелёта, что крутится не туда, что летит поверх текста.
- `qa.motion_lint(slides, theme)` — автоматически: фигура, которая летит поверх текста, стоящего на обоих
  слайдах («точки улетают перед текстом»).
