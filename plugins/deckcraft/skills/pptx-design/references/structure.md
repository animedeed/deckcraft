# Структура колоды: навигация, контейнеры, сочетание стиля и движения

Выводы из колод, которые авторы сделали сами (сайт-презентация продукта, защита технической ВКР), и из показов наших
вариантов. Колода строится от **навигации** и **живых контейнеров**, а не от отдельных красивых слайдов.

## 1. Навигация — система, которая видна всегда

| Приём | Как устроен | Когда |
|---|---|---|
| Меню сайта | строка разделов сверху, текущий подсвечен (как навигация сайта); раздел меняется — подсветка переезжает Morph | продуктовые, «стартап»-доклады, демонстрация интерфейса |
| Метка блока + счётчик | «Блок 2 — Данные» слева сверху, «9\|27» справа; метка меняется затуханием, не переливом | защита ВКР, длинные технические доклады |
| Карта доклада → шапка | на слайде «Что разберём» 3–4 карточки разделов; карточка текущего раздела **вырастает** в шапку/контейнер раздела, остальные уезжают за край и ждут | любой доклад с 3–6 разделами — главный приём пользователя |
| Мотив-указатель | сквозной мотив за краем, часть мотива смотрит на тему (`motif.MotifTrack`, роль pointer) | концептуальные колоды |
| Прогресс внутри раздела | деления части мотива заливаются по темам раздела (4 темы: 25 / 50 / 75 / 100 %) — `pointer(k, part=…)` | разделы с 3–6 подтемами |

Правило: **одна** система навигации на колоду. Меню + мотив-указатель + счётчик сразу — шум.

## 2. Живые контейнеры и парковка

- **Контейнер** — фигура, которая живёт несколько слайдов и меняет роль: карточка раздела → шапка → рамка
  содержимого → снова карточка на итоговом слайде. Имя одно и то же (`!!sec_data`), меняются место и размер.
- **Парковка**: объекты следующих слайдов уже лежат за краем (x < 0 или y > 7,5) и въезжают Morph, а не
  появляются из ниоткуда. Уходящие — уезжают в сторону, куда «движется» рассказ (обычно влево/вниз).
- Текст внутри контейнера меняется затуханием (политика текста), сам контейнер — переливом.

## 3. Сочетание стиля, мотива и движения

1. **Один мотив, одна палитра, один язык движения на раздел.** Пример: раздел «Данные» — точки и их перегруппировка;
   «Модель» — веер связей и сигнал; «Результаты» — столбики и прожектор. Внутри раздела приём повторяется
   (зритель учится читать), между разделами — меняется.
2. **Переход между разделами — одного типа на всю колоду** (если поворот указателя — то на всех разделах; если
   карточка → шапка — тоже везде). Один «особый» переход (портал) в середине колоды выглядит чужим.
3. **Сложная картинка — там, где мало текста**: обложка, открытие раздела, слайд-«вау» раздела (один), данные,
   которые и есть картинка (лепестки = значения), финал. На слайдах с абзацами мотив уходит в фон (backdrop) или
   за край (pointer).
4. **Мотив работает всю колоду, а не только на обложке**: вход (раскрытие), указатель, диаграмма, фон, прогресс,
   финал-рифма. Если мотив после обложки ни разу не меняет роль — он декорация, а не мотив.
5. **Мотив — от темы.** Вино: бокал (уровень = значение), гроздь (ягоды = точки данных), следы бокала (пересечения);
   энергосеть: опоры, провода, волны; документы: листы, штампы, правки; ИИ: слои, дуги внимания.
6. **Движение объясняет, а не украшает**: каждое перемещение отвечает на вопрос «что изменилось?» (выборка
   разделилась, признак важнее, сигнал дошёл). Если ответа нет — объект стоит.

## 4. Где и как применять сложные формы (из лаборатории `pptx-morph/scripts/lab`)

| Форма | Роль в колоде |
|---|---|
| пересечения кругов, разлёт фрагментов | «что уже есть» — части задачи и общая зона; переход от целого к частям |
| слои, которые отслаиваются | уровни детализации: архитектура, слои модели, «под капотом» |
| сегмент кольца-«лупа», бегущий по кругу | цикл процесса, текущий шаг; навигация по кругу этапов |
| орбиты, спирали | время, итерации, эпохи обучения |
| изометрия, кубы, глубина | архитектура системы, стек технологий, «слои» данных |
| мотивы темы (бокал, гроздь, опоры) | обложка, указатель, фон, данные — сквозная линия |
